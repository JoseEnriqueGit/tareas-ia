 Objetivo y contexto

  Construir en 8 horas o menos una PWA móvil donde una persona escribe en lenguaje
  natural lo que tiene pendiente y un agente de IA crea y gestiona las tareas en una base de
  datos Supabase.
  Escenario: eres el apoyo de operaciones de una pequeña empresa. El equipo recibe
  pedidos por mensaje, como "cobrarle a Juan el viernes y mandarle la cotización a Ana
  mañana, urgente", y hoy se pierden en chats. Tu app debe convertir esos mensajes en
  tareas ordenadas, consultables y con fecha.
  La prueba mide cinco cosas: base de datos y seguridad, experiencia móvil y PWA,
  integración de IA con herramientas (agente), criterio para priorizar y comunicación.

 Reglas de la prueba

       Tiempo máximo: 8 horas, incluidos 30 minutos iniciales para leer y escribir un plan.
       Stack: libre en el frontend (React, Next, Vue, Svelte u otro). Es obligatorio usar
       Supabase (Postgres y Auth) y publicar la app en una URL pública.
       IA: puede usar asistentes de código (Claude, Cursor, Copilot). En la revisión final
       deberá explicar cada parte de lo que entregó.
       API de IA: Claude, OpenAI o Gemini. La llave nunca va en el código del navegador;
       debe vivir en una Edge Function o backend.
       Código: repositorio Git con commits frecuentes, no uno solo al final.
       Preguntas: puede hacerle preguntas al evaluador en cualquier momento. Preguntar
       bien suma puntos.
       Alcance: es mejor hacer menos funciones y que funcionen que muchas a medias. Lo
       que no alcance a hacer debe quedar anotado en el README.

Plan de tareas sugerido

Los tiempos son una guía, no una obligación. El candidato decide su propio orden y se
evalúa si lo justifica.

Fase 0: plan (0:00 a 0:30)

     Leer el brief y escribir un plan de una página con lo que hará y lo que dejará fuera
     Crear el repositorio y el proyecto de Supabase
     Escribir las dudas para el evaluador

Fase 1: base (0:30 a 1:30)

     Crear el proyecto frontend y conectar Supabase
     Implementar registro, inicio de sesión y rutas protegidas (RF-01, RF-02)
     Diseñar las tablas (por ejemplo tasks y chat_messages) y las políticas RLS (RF-03)

       README con instrucciones, decisiones y lista de lo que quedó fuera

       Crear dos usuarios de prueba para el evaluador

 Cambio sorpresa

  A las 3:30 h el evaluador entrega este mensaje, sin avisar antes: "El jefe quiere ver las
  tareas de todo el equipo. Necesitamos un rol de supervisor que vea todas las tareas, se las
  pueda asignar a otros usuarios y filtre por persona."
  Alternativas si se quiere variar la prueba:

 Entregables

    1. URL pública de la app, probada en un celular.
    2. Repositorio Git con el historial de commits y el SQL o las migraciones de la base de

       datos.
    3. README con instrucciones para correrla, decisiones tomadas, y una lista honesta de

       lo que quedó fuera.
    4. Dos usuarios de prueba (con contraseña) para que el evaluador compruebe el

       aislamiento de datos.
    5. Video de 3 a 5 minutos mostrando la app instalada en el celular y una conversación con

       el asistente.
    6. Revisión en vivo de 20 minutos: el candidato explica una decisión técnica y hace un

       cambio pequeño pedido por el evaluador.
